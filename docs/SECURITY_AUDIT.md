## Найдено и исправлено

1. **Подбор пароля** (высокая важность). Вход в систему и `/admin` не ограничивали число
   попыток. Теперь: после 10 неверных попыток под одним логином — блокировка на 15 минут,
   с одного адреса — после 30 (перебор логинов). Настройки `LOGIN_*` в `.env`.
2. **Стандартный секретный ключ** (высокая). Без `DJANGO_SECRET_KEY` рабочий сервер
   запускался со стандартным ключом из кода — с ним можно подделать вход под любым
   сотрудником. Теперь рабочий режим без настоящего ключа не запускается.
3. **Оплата с отрицательной суммой** (средняя). «Оплата» с наличными −500 и картой +600
   выводила бы 500 сом из кассы в обход выдачи. Теперь отрицательные суммы запрещены.
4. **Вечная сессия** (средняя). Сессия жила 2 недели — опасно на общих компьютерах ресепшена.
   Теперь 12 часов без активности (продлевается, пока сотрудник работает).
5. **https-настройки** (средняя). Куки сессии могли уходить по http. Теперь `USE_HTTPS=1`
   включает защищённые куки, перенаправление на https и HSTS — вместе с сертификатом.
6. **Адрес клиента за nginx** (средняя). Сервер видел все запросы с адреса nginx; nginx теперь
   передаёт настоящий адрес — нужно для блокировки по адресу.
7. **Отладочные страницы API** (низкая). В рабочем режиме API отдаёт только JSON.
8. **Размер результата анализа** (низкая). Не больше 500 показателей в одном результате.
9. **Камера и микрофон** (низкая). Заголовок `Permissions-Policy`: камера — только самой
   системе, микрофон и геолокация — никому.

## Что нужно сделать при установке (не код)

- **https** в сети клиники и `USE_HTTPS=1` — пароли и данные не идут открытым текстом.
- **Шифрование диска сервера** (BitLocker) — при краже сервера данные не прочитать.
- **Копии вне клиники** — раз в неделю на зашифрованный диск или в облако; папку копий
  держать на другом диске. Сейчас копии не шифруются: доступ к папке копий = доступ ко всем данным.
- **Сильный пароль администратора** и отдельные учётные записи для каждого сотрудника;
  у учётной записи планшета — только роль «Планшет подписи».
- **Сервер — только в локальной сети**: порт 80/443 не пробрасывать в интернет. Если нужен
  доступ извне (мобильное приложение) — через VPN.
- **Обновления**: раз в месяц `make prod-update`; перед обновлением система сама делает копию.

## Принятые ограничения

- Сотрудник с правом на раздел видит все записи раздела (например, все счета) — доступ
  разграничен по ролям и складам, а не по отдельным клиентам. Для одной клиники это норма.
- Две одновременные оплаты одного счёта: вторая не теряется — уходит в аванс клиента.
