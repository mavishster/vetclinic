# ADR-013. Модель прав

- **Статус:** принято
- **Дата:** 28.10.2026

## Контекст
Разные сотрудники — разные доступы; часть действий требует отдельных разрешений.

## Решение
Роль × модуль × действие (просмотр, редактирование, удаление, администрирование) + точечные права (например, «проводить документы по любым складам»).

## Альтернативы
Только роли без действий — слишком грубо; права на каждое поле — слишком сложно.

## Последствия
Строится на стандартных правах и группах Django.

## Реализация (этап 1, шаг 3)
- Роль — группа Django; права — стандартные права моделей (view/add/change/delete).
- Права задаются **по каждой сущности отдельно** (справочник, документ, раздел данных): `core.services.set_entity_permissions(role, "clients.species", {"view", "edit", "delete"})`; «редактирование» = add + change. `set_module_permissions()` — то же сразу для всех сущностей раздела (уточнение по замечанию заказчика 29.10.2026: кому-то нужны только печатные формы, кому-то — только пользователи).
- Строки таблицы прав строятся автоматически из моделей модулей: новый справочник появляется в таблице сам. Служебные таблицы скрываются через `Meta.default_permissions = ()`. Управление ролями (`auth.group`) показано в разделе «Администрирование».
- Все API по умолчанию проверяют права (`core.api.permissions.ModelPermissions`), включая право просмотра для чтения. Открытые адреса объявляются явно.
- Точечные права (например, «проводить документы по любым складам») добавляются в `Meta.permissions` моделей соответствующих модулей.
