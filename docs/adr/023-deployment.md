# ADR-023. Развёртывание на сервере клиники

**Статус:** принято · 01.11.2026

## Контекст
Система работает на одном сервере в клинике (ADR-001), сервер — Windows. Нужны: один адрес
для всех компьютеров, надёжный запуск после перезагрузки, ежедневные резервные копии
с проверкой, что из них можно восстановиться, и простая установка без администратора Linux.

## Решение
- **Docker Compose, отдельная конфигурация `docker-compose.prod.yml`:** db (PostgreSQL),
  backend (gunicorn), worker (Django-Q2), web (nginx), backup. Все с `restart: unless-stopped`.
- **Один Dockerfile — два образа:** `dev` (инструменты проверок, код с компьютера) и `prod`
  (только нужное для работы, код в образе, не от root).
- **nginx — единая точка входа на порту 80:** собранный интерфейс, `/api` и `/admin` —
  в backend, `/static` — оформление админки. `index.html` не кэшируется (обновления видны
  сразу), файлы с хешем в имени кэшируются на год. Один адрес — значит, без CORS и проблем с CSRF.
- **База наружу не открыта** — её порт есть только внутри сети Docker.
- **Резервные копии — отдельный контейнер на образе postgres** со скриптами (`deploy/backup`):
  ежедневно `pg_dump -Fc` + архив файлов, хранение N дней; по воскресеньям — восстановление
  последней копии во временную базу и подсчёт клиентов и записей медкарты. Статус — JSON-файлы
  в папке копий; система читает их и показывает администратору на главной (копия старше
  36 ч, неудача или непроверяемая копия — предупреждение). Расписание — простой цикл в shell
  (без cron в контейнере); пропущенная ночью копия делается при запуске.
- **Windows:** Docker Desktop на Windows 10/11 Pro; на Windows Server — Docker Engine в WSL 2
  (Docker Desktop там не поддерживается). Инструкция — `docs/INSTALL.md`.

## Последствия
- Обновление — `git pull` + `make prod-update` (сначала копия).
- HTTPS пока не нужен: система работает только в локальной сети. Появится вместе с облаком
  и личным кабинетом клиента (этапы 5 и 7).
- Копии вне сервера (NAS, внешний диск) — ответственность клиники, инструкция это подчёркивает;
  выгрузка копий в облако — вместе с синхронизацией (этап 5).
