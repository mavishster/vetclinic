# Установка на сервер клиники

Система работает на одном компьютере-сервере в клинике. Остальные компьютеры
открывают её в браузере по адресу `http://имя-сервера` — ничего ставить на них не нужно.

## 1. Что нужно

| | Минимум | Лучше |
|---|---|---|
| Процессор | 4 ядра | 6–8 ядер |
| Память | 8 ГБ | 16 ГБ |
| Диск | SSD 128 ГБ | SSD 256 ГБ + второй диск или сетевая папка (NAS) для копий |
| Сеть | постоянный IP-адрес в сети клиники | — |
| Питание | ИБП (источник бесперебойного питания) | — |

Операционная система — один из двух вариантов ниже.

## 2а. Windows 10/11 Pro — через Docker Desktop

1. Включите WSL 2: PowerShell от администратора → `wsl --install` → перезагрузка.
2. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) (для клиники
   до 250 сотрудников он бесплатный).
3. Docker Desktop → Settings → General: включите **«Start Docker Desktop when you sign in»**.
4. Чтобы система работала после перезагрузки без участия человека, заведите для сервера
   отдельную учётную запись Windows и включите для неё автоматический вход
   (`netplwiz` → снять «Требовать ввод имени пользователя и пароля»).

## 2б. Windows Server 2022/2025 — через WSL 2

Docker Desktop на Windows Server не поддерживается, поэтому Docker ставится внутри Linux (WSL):

1. PowerShell от администратора: `wsl --install -d Ubuntu-24.04` → перезагрузка → задайте
   имя и пароль пользователя Ubuntu.
2. В Ubuntu: `curl -fsSL https://get.docker.com | sudo sh` и `sudo usermod -aG docker $USER`.
3. Автозапуск: Планировщик заданий → «Создать задачу» → при запуске компьютера, от имени
   SYSTEM, действие `wsl.exe -d Ubuntu-24.04 -u root -- service docker start`.
4. Откройте доступ к порту 80 из сети клиники (см. п. 7).

Дальнейшие команды в варианте 2б выполняются в окне Ubuntu.

## 3. Получить систему

```
git clone https://github.com/mavishster/vetclinic.git
cd vetclinic
```

Репозиторий закрытый: Git спросит логин GitHub и токен доступа
(GitHub → Settings → Developer settings → Personal access tokens).

## 4. Настройки

```
cp .env.prod.example .env
```

Откройте `.env` в Блокноте и заполните:

| Настройка | Что указать |
|---|---|
| `DJANGO_SECRET_KEY` | результат команды `make secret` (длинная случайная строка) |
| `POSTGRES_PASSWORD` | сложный пароль базы — **сохраните его** в надёжном месте |
| `DJANGO_ALLOWED_HOSTS` | имя сервера и его IP через запятую, например `vetclinic-server,192.168.1.10` |
| `BACKUP_HOST_DIR` | папка для резервных копий — лучше на другом диске: `D:/vetclinic-backups` |
| `BACKUP_TIME` | время ежедневной копии, по умолчанию `02:00` (сервер в это время должен быть включён) |

## 5. Запуск

```
make prod-up
make prod-admin
```

Первая команда собирает и запускает систему (первый раз — 10–20 минут, дальше быстро),
вторая создаёт администратора. Откройте на сервере `http://localhost` и войдите.

Если команды `make` нет (обычно на Windows), используйте то же напрямую:

| make | без make |
|---|---|
| `make prod-up` | `docker compose -f docker-compose.prod.yml up --build -d` |
| `make prod-admin` | `docker compose -f docker-compose.prod.yml exec backend python manage.py createsuperuser` |
| `make prod-logs` | `docker compose -f docker-compose.prod.yml logs -f --tail=200` |
| `make backup` | `docker compose -f docker-compose.prod.yml exec backup sh /scripts/backup.sh` |
| `make secret` | `docker run --rm python:3.12-slim python -c "import secrets; print(secrets.token_urlsafe(50))"` |

## 6. Компьютеры клиники

В браузере (Chrome, Edge, Яндекс) откройте `http://vetclinic-server` (или IP сервера,
например `http://192.168.1.10`) и сделайте ярлык на рабочем столе.

## 7. Доступ из сети клиники

Брандмауэр Windows → Дополнительные параметры → Правила для входящих подключений →
Создать правило → Порт → TCP 80 → Разрешить → только **Частная** сеть.
Снаружи (из интернета) сервер открывать не нужно.

## 8. Резервные копии

- **Каждый день** в `BACKUP_TIME` — копия базы и файлов (сканы, снимки) в папку
  `BACKUP_HOST_DIR`. Хранятся `BACKUP_KEEP_DAYS` дней (по умолчанию 30). Если сервер
  был выключен ночью, копия сделается сразу при запуске.
- **Каждое воскресенье** — проверка, что из последней копии можно восстановиться:
  копия разворачивается во временную базу, система считает клиентов и записи медкарты.
- **На главной** администратор видит состояние: «Резервные копии в порядке» или
  предупреждение (копии нет больше 36 часов, копия не удалась, проверка не прошла).
- Копия вручную: `make backup`. Проверка вручную: `make backup-check`.
- **Храните копии не только на сервере**: второй диск, NAS или раз в неделю — на внешний диск,
  который лежит в другом месте. Если сервер сгорит вместе с диском копий, копии не помогут.

### Восстановление

```
make restore FILE=vetclinic-2026-11-01_0200.dump
```

Всё, что внесено после этой копии, пропадёт. Команда предупредит и подождёт 10 секунд;
на время восстановления система остановится.

## 8а. Где хранятся данные и как они защищены

**База данных** (клиенты, медкарты, счета, склад, журнал изменений) — PostgreSQL в томе
Docker `pgdata`. Наружу не открыта: к ней обращается только сервер системы.

**Файлы** (сканы, снимки, фото владельцев, подписанные PDF) — в томе `media`, папка
`attachments/ГГГГ/ММ/`. Имя файла на диске — случайное (UUID), настоящее хранится в базе.
Прямой ссылки на файлы нет: они отдаются только через систему, вошедшему сотруднику с правом
«Файлы» (просмотр). В браузере открываются только картинки и PDF, остальные файлы
(HTML, SVG и т. п.) только скачиваются — загруженная «страница» не выполнится внутри системы.
Размер одного файла ограничен (`ATTACHMENT_MAX_MB`, по умолчанию 25 МБ).

**Подписанные документы**: текст фиксируется при отправке на подпись, его контрольная сумма
(SHA-256) напечатана в PDF — по ней видно, что документ после подписания не меняли.

**Что сделать на сервере для безопасности:**
- включить шифрование диска (BitLocker в Windows) — при краже сервера данные не прочитать;
- папку резервных копий (`BACKUP_DIR`) держать на **другом диске** или сетевом хранилище,
  и раз в неделю уносить копию из клиники (зашифрованный внешний диск или облако);
- https в сети клиники (настраивается при установке) — пароли и данные не передаются открытым текстом,
  и работает камера для фото;
- у каждого сотрудника — своя учётная запись и роль; общий пароль «на всех» не использовать.

**Объёмы** (ориентир для клиники на 30–50 приёмов в день):

| Что | В год |
|---|---|
| База данных (медкарты, счета, склад, журнал) | 1–3 ГБ |
| Фото владельцев (≈ 100 КБ, уменьшаются до 800 px) | 0,3–0,5 ГБ |
| Подписанные PDF (≈ 100–150 КБ) | 0,5–1 ГБ |
| Сканы, рентген, УЗИ (1–5 МБ каждый) | 5–20 ГБ — главный объём |

**Как устроены копии.** База копируется целиком каждую ночь и хранится 30 дней
(`BACKUP_KEEP_DAYS`). Файлы не меняются после загрузки, поэтому каждый файл копируется
в хранилище копий (`BACKUP_DIR/files`) **один раз**, а для каждой ночной копии сохраняется
опись — список файлов на тот момент (`vetclinic-ДАТА.files`). По описи восстанавливается
состояние любого из 30 дней. Файл, удалённый в системе, остаётся в хранилище, пока он есть
хотя бы в одной описи, — 30 дней. Поэтому место под копии ≈ 30 × база + один раз все файлы.
Рекомендация: системный SSD от 256–512 ГБ, диск для копий — не меньше двойного объёма файлов
плюс 30 копий базы (на первые годы хватит 500 ГБ – 1 ТБ).

Еженедельная проверка восстановления разворачивает копию базы во временную базу и проверяет,
что каждый файл из описи и каждый файл, на который ссылается база, есть в хранилище.

## 8б. Нагрузка

Веб-сервер обслуживает запросы несколькими процессами (`GUNICORN_WORKERS`). Обычный запрос
выполняется за 20–100 мс, печать PDF — за 0,3–1 с. Один сотрудник в среднем делает запрос
раз в несколько секунд (плюс фоновые обновления: экран планшета — раз в 2 с, вкладка анализов —
раз в 30 с), поэтому 20–30 одновременно работающих сотрудников — это около 10–20 запросов
в секунду. Ориентир:

| Сервер | `GUNICORN_WORKERS` | Одновременно работающих сотрудников |
|---|---|---|
| 2 ядра, 4 ГБ памяти | 5 | до 15–20 |
| 4 ядра, 8 ГБ | 9 | до 40–50 |
| 8 ядер, 16 ГБ | 17 | 80+ |

Узкое место — одновременная печать большого числа PDF: каждый занимает процесс до секунды.

## 9. Обновление системы

```
git pull
make prod-update
```

`make prod-update` сначала делает резервную копию, потом собирает и перезапускает систему.
Изменения базы применяются автоматически.

## 10. Если что-то не работает

- `make prod-logs` — журналы всех частей системы; ошибки видны в последних строках.
- Система не открывается с других компьютеров, а на сервере работает — брандмауэр (п. 7)
  или имя сервера не указано в `DJANGO_ALLOWED_HOSTS`.
- После перезагрузки не запустилась — проверьте автозапуск Docker (п. 2а.3–4 или 2б.3).
